0.1.0.dev2 · Engineering preview

Your first Nomiarch system.

Download the installation kit, run the terminal wizard, and create a local VM with Core, policy enforcement and a local AI model. Return to the same wizard for maintenance.

Start with a local evaluation.

This preview runs a sample configuration check and records evidence. It has a terminal wizard and an API; a browser dashboard and live infrastructure remediation are still to come. No Azure account is needed for this path.

Download preview kit ↗Installation steps ↓

Downloads appear only after both architecture builds pass their release checks. If the release is not available yet, check the build status. Do not use a source archive in place of the offline bundle.

1. Prepare your machine

ItemWhat you need
HostmacOS or Linux with Python 3.11+, OpenSSL and Multipass. Windows/WSL integration is not yet qualified.
Architectureamd64 for Intel/AMD; arm64 for Apple Silicon or ARM Linux. The bundle and Ubuntu image must match.
Guest capacity2 CPUs, 8 GiB RAM and 40 GiB disk recommended for the included small model. Leave additional space for downloads, staging and backups.
VM imageAn approved Ubuntu 24.04 cloud image and its publisher-verified SHA-256.

Install Python and Multipass while connected. Check the tools before entering the isolated environment:

python3 --version
openssl version
multipass list

Actual Multipass host combinations remain under evaluation. No Docker, Git or Python package installation is required for the downloaded controller.

2. Download and verify the kit

On the preview release page, choose all four matching assets:

  • nomiarch-controller-amd64.zip — the wizard and offline guide.
  • nomiarch-amd64.tar — Core, runtime, policies and model.
  • nomiarch-amd64-public.pem — the verification public key.
  • SHA256SUMS-amd64.txt — file checksums.

For Apple Silicon or ARM Linux, use the files labelled arm64 instead. Obtain the matching Ubuntu 24.04 cloud image and verify its publisher-signed checksum information separately.

Compare download hashes with the release checksums using shasum -a 256 FILE on macOS or sha256sum FILE on Linux. Each preview architecture/build has its own signing key. Approve the public PEM fingerprint through your trusted channel before transfer. A key and checksum from the same untrusted media are insufficient.

3. Transfer and launch the wizard

For an air-gapped evaluation, transfer the verified kit and image into an already isolated host and administration network. The installer uses local files; it does not disconnect your host or establish a physical air gap.

Extract the controller ZIP to a permanent location. Open Terminal in its nomiarch folder:

python3 -m nomiarch bootstrap wizard
  1. Choose Install.

    Select the signed bundle and approved public key.

  2. Select your Ubuntu image.

    Supply the local image path and trusted SHA-256.

  3. Size the VM.

    Choose a name, CPU, memory and disk. Keep the defaults for the first test.

  4. Keep the system.

    Answer “no” to deletion after testing if you want to try upgrades later.

  5. Review and install.

    Confirm the settings. The wizard creates the VM, installs Core and checks the real local model.

Keep the printed run directory under .nomiarch/runs/. It contains the state needed for maintenance. Do not share its private logs or state publicly.

4. Check the first result

Expect validation.status: passed, a completed sample task and a local-model explanation. Two failing sample controls and one passing control are deliberate. Unauthenticated access and the forbidden tool should be denied.

Launch the wizard again and choose Verify to run another sample task and save verification.json. Status displays the last saved controller state; it is not a live health check. Worker network probes cover selected destinations, not every possible path. Physical air-gap qualification remains outstanding.

5. Upgrade with the same wizard

Download and verify a newer controller and matching signed bundle on a staging machine. Approve its public key, then transfer the files. Extract the new controller into a separate folder and point it to the original installation state:

python3 -m nomiarch bootstrap wizard --state-dir /absolute/path/original/nomiarch/.nomiarch

Choose Upgrade, select your installation, and supply the bundle, public key and an age public recovery recipient. Generate the recovery identity on a trusted machine with age-keygen -o recovery-key.txt and obtain its public recipient with age-keygen -y recovery-key.txt. Keep the private recovery key separately; do not enter it into the wizard.

The controller takes an encrypted backup before changing the system. The guest checks compatibility, snapshots its data, installs and verifies the release. Expect downtime. This preview refuses K3s migrations and has no automatic rollback. Keep the backup and receipt. See the recovery procedure.

Until another version exists, selecting the same bundle rehearses backup and reinstallation; it does not prove migration between versions. Repair requires the installed release bundle. Back up exports an encrypted recovery package.

6. Remove your test VM

Export any needed backup first. Use the exact run directory printed during installation:

python3 -m nomiarch bootstrap destroy --run /absolute/path/.nomiarch/runs/RUN_ID

This permanently deletes that VM and its disks. Require cleanup.status: deleted before discarding its controller state.

If something stops

  • Missing prerequisite: install it on the staging side and confirm it works before isolation.
  • Checksum or signature mismatch: stop and replace the artifact through your trusted process.
  • Wrong architecture: choose matching host, image and bundle.
  • Configuration already exists: choose a maintenance action, or use --output env.second.json for a deliberate second installation.
  • Interrupted install: retain the run directory; inspect status, then repair the retained VM or remove it before trying again. A new install creates a new run.

What about Azure?

The new-VM wizard currently targets local Multipass. Azure and existing-host installation use the technical guide; their retained installations can use the maintenance wizard. Live Azure provisioning remains unqualified. Azure is a private cloud profile with possible charges, not a physical air gap.
