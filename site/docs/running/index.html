Desktop preview · 0.1.0.dev4

Download. Open. Set up.

Choose your computer, open the wizard and decide where Nomiarch will run. You review your configuration and approve a plan before the system is created.

Reserve 8 GB of memory and at least 50 GB of free disk space for the first evaluation. A small Linux VM will house Core, the model and your system data.

Early evaluation release.

The desktop apps are unsigned, and the Mac app is not notarized. Your computer may show a warning or block the app. Real customer VM installation and physical air-gap testing remain under evaluation.

1. Download and open the wizard

Windows macOS Linux

Set up on Windows

For Windows 11 Pro, Enterprise or Education on Intel / AMD with Hyper-V. Windows Home and ARM Windows are not supported in this preview.

Download for Windows ↗
  1. Download the app above, then open NomiarchSetup-windows-x64.exe from Downloads.
  2. Choose Set up this computer, enter your project details and choose personal or organisation use.
  3. If requested, choose Enable Hyper-V, approve the Windows administrator prompt and restart your computer. Open Nomiarch Setup again after restarting.
  4. Choose Install VM support if it is missing. Complete Canonical's installer, then return to the wizard and choose Check again.

This unsigned preview may trigger a Windows security warning. On a managed computer, ask your IT administrator whether evaluation is permitted. Keep Windows security protections enabled.

For Macs with an Intel processor.

  2. Move NomiarchSetup to Applications and double-click it.
  3. If Apple shows “NomiarchSetup” Not Opened, follow the steps below.

Apple could not verify NomiarchSetup?

This preview is unsigned and has not been notarized by Apple. If you downloaded it using this page and trust it for testing on your Mac, you can allow this app:

  1. Click Done on the warning.
  2. Open Apple menu → System Settings → Privacy & Security.
  3. Scroll to Security. Find the NomiarchSetup message and click Open Anyway.
  4. Confirm with Touch ID or your password if requested, then click Open.

This saves an exception for NomiarchSetup. Apple's official opening instructions ↗

If the button is missing, try opening the app once more and return to this settings page. On a managed Mac, ask your IT administrator if the option is restricted. Keep your Mac's security protections enabled.

Once the app opens, choose Set up this computer and complete your project and configuration choices. If requested, choose Install VM support and complete Canonical's installer. Return to the wizard, select Check again, then continue below.

Set up on Linux

The reference desktop is Ubuntu 24.04 on Intel / AMD. Other Linux distributions are not yet qualified for this preview.

Download for Linux ↗
  1. Download the app above. In your file manager, open its properties and allow the file to run as a program.
  2. Open NomiarchSetup-linux-x64 and choose Set up this computer.
  3. If VM support is missing, install Canonical Multipass through your approved software manager. Return to Nomiarch Setup and choose Check again.

Linux VM support is installed separately in this preview. Canonical's installation guide ↗

2. Choose where it runs

For your first end-to-end test, choose Set up this computer → Personal evaluation → Isolated VM. Enter short project and environment names, such as acme and evaluation, and choose a new configuration folder. Personal evaluation can keep a local approval record.

A VM (virtual machine) is a separate computer running inside your computer. Windows or macOS hosts the wizard; a Linux VM holds Nomiarch, its local AI model and data. The wizard checks VM support and guides its installation when it is missing.

For an organisation, choose a customer repository and designated human reviewers. For cloud installation, choose Set up in the cloud — Azure and follow the Azure steps. For an existing disconnected site, use the offline steps.

3. Let the app prepare the files

Choose Download and verify automatically. Nomiarch downloads the runtime, local model and matching Ubuntu image, checks the files and verifies the Core signature. You see download progress in the app.

Inside a disconnected site, choose Use files I brought into this environment. The app checks the local kit and stops if anything is missing.

4. Review your configuration and plan

  1. Choose a system name and keep the recommended CPU, memory and disk settings for your first test.
  2. Select Create my configuration. Open the folder to inspect your settings and the installation recipe. No VM has been created.
  3. If you chose an organisation repository, have a designated person approve and merge the configuration PR using the repository steps below.
  4. Choose Prepare deployment plan. Review the destination, capacity, network mode and proposed resources. Azure resources incur charges.
  5. Choose Approve this plan and create the system. Keep the app open while it creates the new VM, installs Core and checks the result.

Approval belongs to the exact saved plan. Changed settings or admitted files require a new review, and plans expire after one hour. Your existing VMs are kept in place.

5. Check your system

When setup says Your system is ready, open Manage my installation → Verify. The sample task deliberately includes two failing controls and one passing control. The local guest network check is separate.

For live measurements, choose Observe and review foundation changes → Check this environment with Core. Core compares observed capacity, its running release and outbound policy with your configuration. With a GitHub read token, it also checks the repository revision. There is no browser dashboard in this preview.

Azure installation

  1. Choose Set up in the cloud — Azure and complete your project and repository choices.
  2. Select Sign in to Microsoft Azure. Enter the displayed code on Microsoft's sign-in page and complete sign-in there. Nomiarch does not ask for your account password.
  3. Choose your subscription, region and a privately reachable subnet. Your administrator must provide the VPN/private route and management range.
  4. Choose the VM size and matching capacity. The wizard records an exact Ubuntu image version and generates a customer-owned Terraform scaffold.
  5. Prepare the files, review the configuration and saved resource plan, then approve deployment.
Private cloud, with clear prerequisites.

This first cloud recipe supports Azure and requires an existing private administration route. It does not create a VPN gateway or Bastion. The VM has no public IP, but Azure platform services remain dependencies. Cloud isolation is not a physical air gap.

Organisation repositories and human approvals

  1. Select Private GitHub repository with human review. Enter the customer owner, a dedicated repository name and the human reviewer logins. Separate multiple logins with commas.
  2. Provide a customer GitHub token in the app. The token stays in memory. Repository creation needs administration access, and your GitHub plan must support protected private branches.
  3. Choose Create a NEW private customer repository, then Open a configuration pull request. An existing repository must already have the required protection and be dedicated to this scaffold.
  4. Have a designated person other than the proposer approve the final PR commit and merge it. Enter the merged PR number in the wizard.
  5. Prepare and approve the deployment plan. The app checks the current repository contents, protection and human review again before applying.

Use a separate account for proposals and human-controlled deployment credentials. Core gets neither the GitHub token nor the cloud credentials. State, keys and private deployment plans stay outside Git. Back up the controller's private installation records separately from your configuration.

Azure scaffolds use a pinned Terraform/OpenTofu module. Local VM lifecycle currently uses a Multipass adapter and a declarative configuration file, with the same approval rules. A native Terraform provider for local VMs is not included yet.

Let Core propose a repair

On the observation screen, you can run a check manually or enable checks every minute while the app and that screen stay open. If supported settings drift, the controller can export Core's bounded repair request or open a customer PR. A pending proposal prevents repeated automatic PRs.

Review and merge the PR, open Review a proposed configuration folder, prepare a fresh plan and approve it. Core cannot approve or apply its own proposal. Changed repository or release versions need separate review; they are not silently adopted as the new baseline.

Upgrade through the same wizard

  1. Get the desktop release that admits the new Core version and prepare its download kit.
  2. In Manage an installation, select your system and choose Upgrade.
  3. Select the kit's signed bundle and public key. Save the new private recovery key separately from backups.
  4. Review the operation request. Organisation customers need a new human-approved PR for this upgrade.
  5. Prepare and approve the upgrade plan. The controller exports an encrypted backup before starting the release change.

Repair and removal also get their own operation request and plan. Approval to install does not authorize later replacement or deletion. Expect downtime during upgrades. K3s migrations and automatic rollback are not supported. Recovery procedure ↗

Installing at a disconnected site

  1. On a connected computer, choose Download an offline kit. Windows/macOS kits include the pinned VM-support installer.
  2. Transfer the kit and app through your approved process to a computer with the same operating system and CPU architecture. Admit Linux VM support through your software manager.
  3. On the destination, choose Disconnected site. If VM support is missing, select the installer from the admitted kit.
  4. Choose the local kit, review the configuration and approve the plan. Missing files stop setup instead of triggering a download.

The local guest boundary blocks new outbound IPv4/IPv6 traffic, with fixed exceptions for local runtime networking and administration replies. It is applied after VM creation. Verify it after a reboot and test your actual network paths.

A VM is not automatically air-gapped.

The wizard does not disconnect your host's Ethernet, Wi-Fi or radios. A physical air gap requires a disconnected host/site and controlled transfers. Public GitHub cannot operate inside that boundary. Internal organisation repositories are currently an export path; deployment stops until an internal approval integration is provided. Personal offline evaluation can use local human approval.

Finished testing?

Save any backup you need, then select the installation and choose Remove selected VM. Review its removal request and plan. Organisation users need a human-approved removal PR. Approving removal permanently deletes the recorded VM and disks.

If setup stops

Mac app blocked before it opens? Follow the Mac opening steps.

The app shows the error and preserves installation records. Retry a download to reuse verified completed files. For an interrupted installation, use Manage to inspect, repair or remove the retained VM. Starting a new install creates another VM.
